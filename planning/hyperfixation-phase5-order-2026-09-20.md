> **Finding (X3, 2026-09-20): the first two real calls put `/api/status` into `degraded` on a drift that was only a
> column's scale.** Haiku 4.5 billed $0.000838 and $0.000855 — exactly list price for 488/70 and 485/74 tokens — but
> `hf_budget_period.spent_usd` was `numeric(12,4)` against `hf_llm_call.cost_usd`'s `numeric(12,6)`, so the period read
> `spentUsd "0.0017"`, `ledgerUsd "0.001693"`, `driftUsd "0.000007"`, and `hf doctor` WARNed `drift`. Fixtures cost 0, so
> nothing before a real call could show it. The settle is `spent_usd = spent_usd + cost_usd`, so the rounding was of the
> running total and grew per call: 200 settles of those two prices land on `0.1700` against a ledger of `0.169300`, and a
> period capped at `$0.004900` admits six calls of $0.000838 where five fit. Fixed in core 0.1.8 — migration
> `0009_budget_spent_scale` widens the column to `numeric(12,6)` and repairs the rounding it had already accumulated;
> drift is now subtracted in Postgres at that scale, so a settled period reads `0.000000` and not a tolerance.

## Risks

1. **`max_connections`** may be Postgres's default 100; two apps fit, four do not. P0 reads it; raising it is a Coolify
   Postgres setting and a restart — not in this phase.
2. **Name-prefix collisions** in the backup step's `databases_to_backup` match and the tunnel's container discovery:
   verified for one app only. Adversary target (a).
3. **Downstream matrix cost** triples per core PR; if it exceeds ~10 min, cache the template's install.
4. **Drift tolerance can hide a lossy dump** if a listed table is not truly append-only. The list is explicit and
   `hf_run`/`hf_llm_call`/`hf_action_log`/`hf_approval`/`hf_activity`/`hf_audit` only; anything with deletes stays exact.
5. **The bump PR on a private repo** needs the App installed there — verified only by hand (personal account).
6. **A release between W1 and W2** opens two bump PRs, not three; that is expected, not a defect.
7. **Real keys.** A leaked provider key is real money. Keys enter only through the operator config (0600) and Coolify's
   environment; the template's scrubber covers logs and Sentry; the provider account carries a hard spend limit at or below
   the cap. If a key ever appears in a log or transcript, rotate it before anything else.

**Adversary targets before X3:** (a) everything two apps on one box share — Coolify project/app naming, compose service and
network names, the backup-schedule match, `HF_DB_CONTAINER` discovery, the S3 storage, the Cloudflare sender, the state
directory — and any of them keyed by a prefix rather than an exact name; (b) C2's append-only list — a table where a
restore losing rows reads as "drift"; (c) `publish-ci` opening three PRs when one repo refuses (must open the others and
report the one); (d) the first real provider call — a key present in any error path, log line, Sentry event or state
file.

**Verification, per chunk:** core `pnpm -w typecheck lint test api-extractor` from a clean clone; the named gates above;
template `pnpm typecheck lint test`; for anything touching the box, the P0 pre-flight and the X3/X4 tables.
